# Ресёрч ускорения рендера на Cloud Run — замеры + рычаги + экономика (2026-07-02, вечер)

> Статус: **RESEARCH / PROPOSAL** (ничего из предложенного ещё НЕ реализовано).
> Контекст миграции и карта сервисов — `docs/CLOUDRUN_AND_RENDER_PERF.md`. Этот отчёт закрывает её
> §4.0 («сначала замерь») и уточняет §4: боевой E2E-замер СДЕЛАН, и главный тормоз оказался НЕ тем,
> что предполагалось.

## TL;DR

1. **Фан-аут работает**: тот же 86-мин source (13 клипов) — 60,5 мин in-process → ~31 мин фан-аутом (~2×).
2. **Главный тормоз — баг в коде, не платформа**: `_refine_cut_native` (stage3_reframe.py:720-761)
   на каждую кандидат-склейку декодирует видео от начала клипа **до КОНЦА source-файла** (в ffmpeg-команде
   нет `-t`/`-frames:v` капа). Стоимость ∝ `C·(S−o)` — растёт с длиной source ЗА клипом. Замеры это
   подтверждают позиционно: клипы из начала 86-мин видео ждали 491–776 с, клипы из конца — 20–40 с.
   Фикс — одна строка, LOW risk, кадровую сетку не трогает (выбор кадра не меняется, только объём декода).
3. **GPU не нужен для маржи** — это чисто latency-игра (стоимость/клип флэт-to-хуже). Дешёвые победы:
   фикс бага + одна волна фан-аута + preview из хвоста + 8vCPU рендер-бокс.
4. Реальная маржа (Cloud Run, instance-based): Starter ~50%, Pro ~35%, PAYG ~75%. Старые «~73–90%» в
   `billing.py`/`BENCHMARKS.md` — эпоха Modal, устарели.

## 2. Куда уходит время клипа (модель из кода)

`S`=длина source, `o`=офсет клипа, `L`=длина клипа (20–60 с), `C`=склейки в клипе. Один quip-render
execution = `cloudrun_job.main` → `tasks.fanout_render_clip_job` → `run.render_one_clip`.

| Стадия | Где | Стоимость | Типично |
|---|---|---|---|
| Cold start | импорты/init (torch/cv2/mediapipe ленивые, веса в образе) | фикс | 37–60 с |
| Скачивание source | `storage.download_source` — ВСЕГДА полный файл | ∝ размер source | 5–20 с (100–300МБ); 1–3 мин (1–2 ч source) |
| Scene detect | `detect_scene_cuts` — ffmpeg re-encode сегмента full-res ultrafast + PySceneDetect | ∝ `L·F` | 15–30 с |
| **Refine cut (БАГ)** | `_refine_cut_native` stage3_reframe.py:720-761 — ffmpeg БЕЗ `-t` капа → декод до EOF на каждый cut | ∝ **`C·(S−o)`** | 40–120 с на 8-мин source; **минуты на cut** на часовых |
| Лица + ASD | `asd_reframe.score_tracks_in_segment`: JPG@25fps full-res, ВСЕ кадры в RAM (~9,3 ГБ для 60 с 1080p — вот зачем 16Gi), MediaPipe per-frame; ASD только при ≥2 треках (skip одного трека УЖЕ отгружен), ансамбль **11 окон** (`scorer._DURATIONS`) | ∝ `25·L` (+ASD ∝ `11·кадры трека`) | 40–90 с (+0–120 с ASD) |
| Encode (движок B) | `render_frame_by_frame`: per-frame cv2, GaussianBlur **55×55 на 1080×1920** (fit), LANCZOS4 (fill), пайп в x264 | ∝ `L·F` | 25–46 с (4vCPU) |
| Upload | клип + fanout-result JSON | ∝ размер клипа | 3–8 с |

Координатор: батчи ≤`RENDER_FANOUT_MAX=6` строго друг за другом (dispatch.py:196-205), poll 8 с;
preview_proxy (re-encode ВСЕГО source в 720p) + video_map — **inline-хвост ПОСЛЕ клипов**
(run.py:662-699; на Modal спавнились параллельно, на Cloud Run гейт `modal_spawn_enabled()` их отключил).
8vCPU/32Gi координатор всё это время БИЛЛИТСЯ (idle-poll).

## 4. Платформа Cloud Run — факты (проверено 2026-07, доки переехали на docs.cloud.google.com)

- **Jobs = instance-based биллинг всегда**: Tier 1 (europe-west1) **$0.000018/vCPU-с + $0.000002/GiB-с**;
  минимум 1 мин на инстанс. Рендер 4vCPU/16Gi = $0.000104/с ($0.37/ч); 8vCPU/16Gi = $0.000176/с;
  координатор 8/32 = $0.000208/с ($0.75/ч). Потолок инстанса — **8 vCPU / 32 GiB** (больше нет).
- **GPU L4 для Jobs доступен в europe-west1**: no-ZR ~$0.0001867/GPU-с (~$0.67/ч), авто-квота 3 GPU без
  апрува, старт GPU ~5 с, драйверы предустановлены, **таймаут задачи с GPU — 1 ч**. NVENC официально
  подтверждён (туториал Google «GPU-accelerated video transcoding with FFmpeg on Cloud Run jobs»).
  НО: MediaPipe остаётся CPU; GPU ускоряет torch-ASD + энкод. Клип 4vCPU/16Gi/L4 × 2 мин ≈ $0.035.
- **Cold start**: image streaming автоматический (размер образа < ~10ГБ не критичен); startup CPU boost —
  только Services; min-instances для Jobs НЕТ. Наши 37–60 с — python-импорты, лечится slim-образом/lazy init.
- **Task-array**: одна execution `--tasks=N --parallelism=M` (клип по `CLOUD_RUN_TASK_INDEX`) вместо N
  RunJob-вызовов — меньше API-оверхеда (лимит 180 запусков/60 с), ретраи per-task.
- **Worker pools GA**: тёплый пул (модели в RAM, cold start→0), ~40% дешевле jobs по позиционированию
  Google; 2×4vCPU/16Gi ≈ **$330/мес** стоя. Для интерактивных re-render'ов позже.
- **Ephemeral-disk volume для Jobs (Preview)**: `gcloud beta … --add-volume type=ephemeral-disk,size=10Gi` —
  реальный диск вместо tmpfs-в-RAM → снимает 10ГБ-source-в-16GiB-RAM проблему.
- **Скрытые деньги**: egress ИЗ GCP в R2 (заливка клипов) ~$0.12/GiB ≈ $0.006–0.012/клип; ingress из R2
  бесплатен с обеих сторон; Artifact Registry $0.10/ГБ/мес (чистить старые digests); logging >50GiB/мес платный.
- **Modal-сравнение**: CPU у Modal ~2,7× дешевле ($0.0000066/vCPU-с) + memory snapshots (3–10× старты).
  Эквивалента снапшотов у Cloud Run нет; ближайшее — slim-образ + task-array + (позже) worker pool.
- Spot VM (n2-standard-8 ~$0.15/ч) — в ~5× дешевле, но своя очередь/preemption/ops — reject сейчас.

## 5. Экономика (квота = МИНУТЫ SOURCE, клипы не биллятся)

Revenue/60-мин кредит: Free $0 · Starter $1.50 · Pro $1.17 · PAYG $3.00 (`billing.py:58-103`,
`plans.ts:27-82`). Канонич. джоба 60 мин / 6 клипов (instance-based тарифы):

| Статья | $ |
|---|---|
| Координатор ~20 мин × $0.0125/мин | 0.25 (из них idle-poll ~0.08–0.12) |
| 6 renders × ~340 с × $0.000104 | 0.21 |
| Deepgram 60 мин × $0.0043 | 0.26 |
| Gemini select+hooks+map | ~0.02 |
| **Итого** | **≈$0.74** (+egress ~$0.05) |

Маржа компьюта: **Starter ~50% · Pro ~37% · PAYG ~75%** (минус комиссия Polar 5%+$0.50 — отдельно).
После пакетов 0–2 (рендер быстрее + координатор не простаивает + RAM 16→8): джоба ~$0.5–0.55 →
**Starter ~63% · Pro ~52%**. GPU: клип быстрее ~2×, стоимость флэт-to-+15% → UX-игра, не маржа.
Структурный риск: юзер платит за минуты source, мы платим за КЛИПЫ — короткие видео с кучей клипов =
худшие сделки; Free-видео ≈ $0.5–0.9 чистого убытка каждое; Pro близко к себестоимости.
