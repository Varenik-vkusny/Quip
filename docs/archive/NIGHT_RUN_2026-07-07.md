## B2 — vision subject-hint → reframe (prototype) — committed OFF (`a529ead`)
Flag-gated prototype (`REFRAME_VISION_SUBJECT`, default OFF → byte-identical legacy reframe). When on,
the B1 vision box's subject centre-x is a **tie-breaker in `_pick_target`** (which already-tracked face
a fill shot follows) — never per-frame crop coordinates. Δ=0 grid / region boundaries / fill-vs-fit

Honest assessment (why it stays a prototype):
- The box is per-clip-**window**, not per-shot → in a multi-shot clip where speakers swap sides across
  cuts, one subject-x is applied to every fill shot and can mis-pick later shots. Main limitation.
- It only bites on **clustered** multi-face shots (wide 2-shots go `fit` by design). Cardi B is mostly
  single-speaker → it rarely triggers, so I did **not** burn a render on it (low signal on this content;
  needs a real multi-speaker test video).
- **Container fan-out (Cloud Run) doesn't carry `subject_cx` yet** — only the in-process path does.
  Must be closed before any real ship. Also not persisted across cached reruns.
- Per the REFRAME invariant, needs eyes-on multi-face verification before trusting Gemini's boxes.

Recommendation: keep flag-gated; evaluate on a genuine multi-speaker clip before investing in per-shot
boxes + the fan-out plumbing. **Low priority vs B1** (which is the real win).

## Ease (reframe follow "still a bit abrupt") — root cause found, fix ready (NOT shipped)
**Root cause:** the shipped dead-zone ease is EXPONENTIAL (`cam += EASE*(target-cam)`), which moves
FASTEST on the very first frame of a pan — velocity jumps 0 → peak instantly. That instant velocity
spike is the "too fast / jerky start" you feel. Numerically (synthetic 0.45→0.30 move,
`scratchpad/ease_sim.py`):

| | first-frame velocity jump | peak velocity |
|---|---|---|
| SHIPPED (exponential) | **0.00600 (instant)** ← the jerk | 0.00600 at frame 1 |
| PROPOSED (2nd-order)  | 0.00072 (gradual, ~8× smaller) | 0.00425 ramped over ~8 frames |

**Fix (ready, held per your "leave it"):** make it 2nd-order — ramp the VELOCITY, not the position, so
the camera accelerates smoothly INTO a pan and decelerates OUT (cinematic slow-in / slow-out). ~3-line
change in `_track_trajectory` (`stage3_reframe.py`), + a `_FOLLOW_ACCEL ≈ 0.12` constant:
```
    cam = init_cx if init_cx is not None else sm[0]
    vel = 0.0
    cams = [cam]
    for i in range(1, len(sm)):
        target_vel = _FOLLOW_EASE * (sm[i] - cam) if abs(sm[i] - cam) > _FOLLOW_DEADZONE else 0.0
        vel += _FOLLOW_ACCEL * (target_vel - vel)
        cam += vel
        cams.append(cam)
```
