# Video Map → «Кокпит»: интерактивная карта источника с добычей клипов

> **Статус:** design approved (founder, 2026-07-08). Ветка `feat/video-map-cockpit`.
> **Правило прода:** разработка + локальные тесты; **НЕ деплоим** без явного go.
> Источник-карта текущей реальности: `docs/README.md` §«Объяснимость + Карта видео».

## 1. Проблема (диагноз)

Сейчас Video Map (`apps/web/components/VideoMap.tsx`, монтируется на результатах
`app/(app)/dashboard/page.tsx:433`) — это **эссе-оправдание** под заголовком «Why these clips are
worth it»: связный нарратив + аккордеон глав + инлайновые `[[clip:clip_NN]]`/`[mm:ss]` как **мёртвый
текст**. Для монтажёра это самый бесполезный жанр — он не хочет читать, почему выбрали 30 клипов, он
хочет **быстро понять структуру видео, прыгать по нему и вытащить БОЛЬШЕ клипов**.

Три конкретных провала в коде:
1. **Координаты отрендерены как текст.** `(words 4097-4227)` / `[mm:ss]` — это точки на таймлайне, но
   их нельзя кликнуть/перемотать.
2. **~90% данных выбрасывается.** Компонент получает полный `ClipOut[]` (hook, key_quote, energy,
   score, thumbnail, пословный тайминг), а использует только `id/start/end` (`VideoMap.tsx:44-47`).
3. **Упущенные моменты невидимы и врут.** Система уже знает, какие моменты нашла, но НЕ нарезала
   (`TimelineSegment.clip_id = null`, `models.py:393-408`). Их не показывают. Хуже: клик по
   ненарезанному моменту молча ведёт в редактор *соседнего* клипа (фолбэк `chapterClipIds[0]`,
   `VideoMap.tsx:162-164`).

## 2. Цель и критерии успеха

Превратить пассивное эссе в **кокпит**, из которого монтажёр:
- **видит форму** всего видео (главы + моменты + покрытие «что нарезано / что упущено»);
- **навигирует** — клик по чему угодно перематывает инлайн-превью источника (покадрово);
- **действует** — открывает готовый клип ИЛИ **достаёт новый** из упущенного момента / выделенного
  куска.

**Definition of done:**
- `just check` зелёный; новая pure-логика границ покрыта TDD.
- Локальный E2E: добытый клип на реальном видео (Cardi B source) режется **чисто на границе** и
  визуально идентичен по качеству краёв авто-клипам.
- Ничего в проде не сломано (не деплоим; ветка изолирована).
- Экономика/гейт реализованы серверно (нельзя обойти с фронта).

## 3. Украденные паттерны (из ресёрча — Descript / YouTube / Snipd / Mux / VS Code minimap)

Все ложатся на данные, которые уже есть:
- **Один объект — три отображения** (YouTube-чаптеры): список-аутлайн + подписанные сегменты *на
  таймлайне* + тултип при наведении.
- **Density-overlay = миникарта медиа** (YouTube «Most Replayed»): полоса покрытия + (опц.) кривая
  energy/score по таймлайну.
- **Две гранулярности, обе кликабельные** (Descript/Snipd): грубые главы + мелкие моменты, каждый —
  точка перемотки.
- **Живое «вы здесь»** — покадровая подсветка через `requestVideoFrameCallback` (наш же урок про
  reframe: rVFC > `timeupdate` ~4Hz).
- **«Найти хорошие клипы» → кандидаты, которые черри-пикаешь** (Descript Underlord) = наш deferred
  «создать клип из момента».

## 4. Дизайн: раскладка и три глагола

Desktop-раскладка (mobile — стек: плеер → таймлайн → аутлайн, таймлайн скроллится горизонтально):

```
┌─ VIDEO MAP ─────────────────────────────────────────  [EN/RU] ─┐
│  Cardi B interview · 1:26:03 · 14 глав · 30 клипов · 28 упущено │
│  ┌────────────────────────┐   ┌─ АУТЛАЙН (скролл) ───────────┐ │
│  │   превью источника     │   │ ▾ 1 Dream guest        0:00  │ │
│  │   16:9, seek по клику  │   │    • hidden talent   ● клип  │ │
│  │        ▶ 12:04         │   │    • unnoticed       ○ упущ. │ │
│  └────────────────────────┘   │ ▸ 2 Childhood          5:33  │ │
│  ┌─ ТАЙМЛАЙН (весь источник) ─────────────────────────────────┐│
│  │ [ гл.1 ][ гл.2 ][  гл.3  ]…            ← подписанные главы  ││
│  │   ●   ○ ●    ●  ○  ○   ●  …            ← моменты (цвет=kind)││
│  │  ▓▓░░▓▓▓░░░▓▓░░▓▓▓▓░░░░▓▓              ← покрытие (▓=нарезано)│
│  │  └───────────────┃ playhead────────────────────────────┘   ││
│  │  [drag → выделил кусок → «＋ Сделать клип»]                 ││
│  └────────────────────────────────────────────────────────────┘│
│  ▸ Why these clips work   (нарратив свёрнут сюда)               │
└─────────────────────────────────────────────────────────────────┘
      ↓ ниже — существующий грид клипов (без изменений)
```

**Глагол 1 — Видеть.** Главы = подписанные сегменты. Моменты = цветные тики по `kind`
(tension/quote/emotional/insight/funny, палитра из `lib/momentKinds.ts`). Полоса **покрытия**: ▓ где
интервал момента пересекается хоть с одним клипом, ░ где нет.

**Глагол 2 — Навигировать.** Клик по главе / моменту / строке аутлайна / точке таймлайна →
инлайн-превью (`preview.mp4` прокси, уже есть per job) перематывается туда и играет. Playhead +
подсветка активной строки двигаются синхронно **через `requestVideoFrameCallback`**.

**Глагол 3 — Действовать.**
- момент/глава уже клип → чип **«Открыть клип #N»** → редактор;
- **упущенный** момент (`○`) или выделенный кусок → **«＋ Сделать клип отсюда»** (см. §6);
- `○`-момент **не притворяется клипом** (у него кнопка «сделать», а не фейк-ссылка) → чинит текущую
  ложь с фолбэком.

**Нарратив-эссе** не удаляем — **демотируем** в раскрывашку «Why these clips work» внизу (доверие/
объяснимость; `[[clip:]]`-ссылки внутри остаются). `chapter.summary` переезжает в раскрытие строки
аутлайна.

## 6. Логика рендера добытого клипа (ядро — то, что просил продумать founder)

### Когда: строго on-demand, один клип, стримингом
Ничего заранее. Клип режется **только по клику** «Сделать клип». Дальше — существующий механизм:
1. клип персистится `pending` (пустой `video_url`, статус `rendering`) и **всплывает в гриде со
   скелетоном «Rendering…»** (тот же паттерн инкрементальной выдачи, `set_clips_pending`/
   `set_clip_ready`);
2. спавнится **тот же per-clip контейнер `reframe_render_clip`**, что и для авто-клипов →
   **инвариант кадровой сетки НЕ трогаем** (переиспользуем готовый рендер как есть).

**Дешёвая защита от необдуманных рендеров:** `○`-момент до рендера показывает кадр-превью из
источника (`PendingThumb` уже грабит кадр из прокси без CORS). Юзер видит, ЧТО достаёт, до траты
рендера — это и UX, и защита маржи.

### Обрезка «ровно на нужном моменте» — гарантия чистого края
Подводный камень: у момента карты только секунды (**пословные индексы выброшены** при генерации).
Наивный ffmpeg-cut по секундам даст рваный край. Поэтому добыча идёт через **ту же границу-логику,
что и авто-клипы**:
1. секунды → ближайшие слова (`_nearest_word_index`, `video_map.py:189-201`);
2. снап краёв к границам слов (`snap_start_index`/`snap_end_index` из `postprocess`);
3. **аудио-осознанная доводка** `refine_boundaries_audio` — срезает филлеры по краям + снапит конец
   во «вдох» по кривой `loudness` (для джобы **уже посчитана**, лежит в артефактах);
4. safe-pad старта −150мс + расширение до ≥20с (`moment_to_interval`, `video_map.py:204-250`).

→ добытый клип получает **идентичное авто-клипам качество краёв** (те же протестированные pure-
функции). Хук/why/цитату **сидим из `moment.label`/`why`** (без лишнего LLM-вызова = дешевле); опция
«перегенерить хук» — существующий `/hook/regenerate`.

Тот же путь для **drag-select куска** (не найденного заранее): строим сегмент из `[start,end]` → снап
→ доводка.

### Окно доступности: source живёт 60 дней
Рендер требует полный source; он чистится через 60 дней (`cleanup_stale_sources`; клипы — вечно).
Значит добыча возможна **~60 дней после загрузки**; потом кнопка гаснет с честным сообщением
(«исходник больше не хранится — перезагрузи, чтобы достать ещё»). **Никаких тихих фолбэков** —
серверная проверка наличия source, явный статус.

### Идемпотентность
Повторный клик на тот же момент/кусок не должен рендерить дважды — гард по ключу (round-to-word
`start/end`); при гонке возвращаем уже созданный clip_id.

## 7. Экономика и гейт (финал, утверждено)

**Гибрид (маржа):**
- Рендерим **только добытое** (не все 58 заранее) — в среднем сильно < 30 рендеров/видео = экономия
  компьюта. Это и есть маржа: не жжём впустую.
- Добыча **бесплатна, пока суммарно клипов ≤ 30** (авто-выбранные + добытые). В пределах уже
  оплаченного «до 30 клипов из видео» → **худший случай = обычная 30-клиповая джоба**, её маржа уже
  заложена (Starter ~50% / Pro ~37%) → **нулевой новый риск**.
- **Сверх 30** из одного видео → **хард-пейволл за конкретный клип** (доплата per-clip).
- Порог `30` = тюнящийся knob (`config`), не хардкод.

**Гейт (премиум):** добыча — **только Pro/Studio**.
- Free/Starter видят ВСЮ карту и все `○`-моменты (апселл: «смотри, сколько ещё в твоём видео»), но
  кнопка «Сделать клип» → пейволл-ната (upgrade CTA).
- Studio ещё не live (миграция 0016) → гейт на `plan ∈ {pro, studio}`; Studio включится сам.

**Реализация — серверно (нельзя обойти с фронта):**
- `POST /jobs/{id}/clips` за `_require_owned_job` + проверка `plan ∈ {pro, studio}` (иначе 402/403 с
  кодом upsell).
- Подсчёт `len(job.clips)`: < 30 → рендер бесплатно; ≥ 30 → требуем оплату per-clip (PAYG-путь;
  идемпотентно per new `clip_id`, как существующая usage-идемпотентность).
- Источник правды цены/гейта — `billing.py` (+ зеркало `lib/plans.ts` для UI-состояний). Менять
  ОБА (CLAUDE.md money-path).
- Цена per-clip сверх 30: knob (дефолт прикинуть из `docs/BENCHMARKS` рендер-юнит-экономики).
